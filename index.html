1. The Big O ladder (fastest to slowest)

      
O(1) → O(log N) → O(N) → O(N log N) → O(N²) → O(2ᴺ) → O(N!)

      
    
        
  • O(1) constant: read arr[i], hash lookup, push/pop.
    • 
        
  • O(log N) logarithmic: anything that halves or doubles each step (binary search, balanced BST, heap insert).
    • 
        
  • O(N) linear: one loop, linear search, walking a linked list.
    • 
        
  • O(N log N) log-linear: merge sort, heap sort, quicksort (average).
    • 
        
  • O(N²) quadratic: loop inside a loop; bubble, selection, insertion sort.
    • 
        
  • O(2ᴺ) exponential: plain recursive Fibonacci.
    • 
      

      
How to read code: one loop = N. Loop inside a loop = multiply. Loops one after another = add (keep the bigger). A loop variable that doubles or halves = log N. Drop constants and smaller terms.

3. Sorting table (memorize this)

      

        
SortBestAverageWorstHow to spot it

        
BubbleO(n)*O(n²)O(n²)Swaps neighbors a[i] and a[i+1]

        
SelectionO(n²)O(n²)O(n²)Tracks index of the smallest, one swap per pass

        
InsertionO(n)O(n²)O(n²)Slides an item backward (j--). Best for nearly sorted.

        
ShellO(n log n)O(n^1.5)O(n²)Keywords: gap, interval. Insertion sort with a shrinking gap.

        
QuickO(n log n)O(n log n)O(n²)Pivot, partition. Worst when already sorted.

        
MergeO(n log n)O(n log n)O(n log n)Split at the middle, recurse, merge. Needs O(n) extra memory.

        
HeapO(n log n)O(n log n)O(n log n)Build a heap, remove the max repeatedly

        
RadixO(nk)O(nk)O(nk)By digit, ones place first. Always 10 buckets. No comparisons.

        
CountingO(n+k)O(n+k)O(n+k)Counts how often each value occurs. Small range of integers. No comparisons.

        
BucketO(n+k)O(n+k)O(n²)Evenly spread values in a range (like 0.0 to 1.0)

      

      
*Bubble sort's O(n) best case needs the "stop if no swaps" flag.

      
Keywords to spot a sort: bubble = swap/exchange neighbors · selection = select minimum, swap with start · insertion = insert/shift element · merge = merge/split in half · quick = pivot/partition · heap = heapify/extract max · shell = gap/interval · radix = digits · bucket = buckets.

      
Other facts: merge sort is stable but needs extra space. Heap sort is in-place but not stable. Selection sort makes the fewest writes. Counting, radix, and bucket are the non-comparison sorts.

4. Trees

      
    
        
  • Binary tree: at most 2 children. BST: left subtree smaller, right subtree larger (whole subtree, not just the child).
    • 
        
  • PREorder = node, left, right (root first). INorder = left, node, right (sorted for a BST). POSTorder = left, right, node (root last). Level order = row by row, uses a queue.
    • 
        
  • Full: every node has 0 or 2 children. Complete: filled row by row, left to right. Perfect: every level full; 2^(h+1) − 1 nodes.
    • 
        
  • Height: edges on the longest path down from the root. Root alone = 0. Root's depth = 0.
    • 
        
  • BST remove: no children → just remove it. One child → link the parent straight to the child. Two children → replace with the in-order successor (or predecessor).
    • 
        
  • Balanced: left and right subtree heights differ by at most 1.
    • 
        
  • AVL tree: strictly balanced BST, fixed with rotations. Best for search-heavy work.
    • 
        
  • Red-black tree: root is black, no red node has a red child, looser balance, faster inserts and deletes.
    • 
        
  • B-tree: nodes hold many keys (order m: up to m − 1 keys, m children). Balanced by splitting and merging. Used in databases and file systems.
    • 
      


      
5. Heaps

      
    
        
  • Max-heap: parent ≥ children, largest at the root. Min-heap: parent ≤ children, smallest at the root. Must be a complete tree.
    • 
        
  • Array form (index i): left child 2i + 1, right child 2i + 2, parent (i − 1) // 2.
    • 
        
  • Heapify (array → heap) is O(n).
    • 
        
  • Insert: add at the end, swap upward. Remove: take the root, move the last item to the root, swap downward with the larger child (max-heap).
    • 
      


      
6. Hash tables

      
    
        
  • Bucket index = key % table_size (the remainder).
    • 
        
  • Collision: two keys, same bucket. Chaining: a list in each bucket. Linear probing: try the next bucket, then the next. Quadratic probing: jump +1, +4, +9. Double hashing: a second hash picks the jump size.
    • 
        
  • Load factor = items ÷ buckets. Too high → resize and rehash.
    • 
      


      
7. Graphs

      
    
        
  • Vertex = dot, edge = line, adjacent = directly connected, degree = edges touching a vertex, path = route, cycle = path back to its start.
    • 
        
  • BFS uses a queue (ripples outward; fewest-edges path). DFS uses a stack or recursion (go deep, then back up).
    • 
        
  • Dijkstra: greedy, shortest path with non-negative weights, O(V²) simple or O(V log V + E) with a heap. Bellman-Ford: dynamic programming, handles negative weights and detects negative cycles, O(V × E). Topological sort: prerequisite order. Minimum spanning tree: connect everything for the least total weight.
    • 
        
  • Adjacency list: O(V + E) memory. Adjacency matrix: O(V²) memory, O(1) edge check.
    • 
      


      
8. ADT → what it's usually built on

      
List, Bag (multiset) → array or linked list · Stack, Queue → array or linked list · Deque → linked list · Set, Dictionary → hash table or BST · Priority queue → heap


      
8b. Algorithm basics

      
    
        
  • Six characteristics: finiteness (it ends), definiteness (clear steps), input, output, effectiveness (steps are doable), generality (solves a group of problems).
    • 
        
  • Factors: modularity, correctness, maintainability, functionality, robustness, user-friendly, simplicity, extensibility.
    • 
        
  • Types: brute force (try everything) · recursive · backtracking (undo bad choices) · divide and conquer · greedy (best choice now, may not be best overall) · dynamic programming (store and reuse results) · randomized · searching · sorting · hashing · encryption.
    • 
        
  • Data flow diagram symbols: process = circle or rounded rectangle · data store = open-ended rectangle · data flow = arrow · external entity = square.
    • 
        
  • Abstraction levels: data type (int, char) → data structure (array, linked list) → ADT (stack, queue, set, map).
    • 
      


      
8c. Programming concepts

      
    
        
  • Static variable: memory set at compile time, fixed size. Dynamic: memory set at run time on the heap, can grow.
    • 
        
  • Strongly typed (Java, Python): no automatic type mixing, 10 + "5" is an error. Weakly typed (JavaScript, PHP): converts for you, 10 + "5" gives "105" in JavaScript.
    • 
        
  • Order of operations: ( ) → ** → unary minus → * / // % (left to right) → + − → comparisons → not → and → or.
    • 
        
  • Loops: break leaves the loop. continue skips to the next pass. pass does nothing. A do-while runs at least once.
    • 
        
  • OOP: constructor = __init__. Inheritance = child gets the parent's stuff. Encapsulation = hide the internals. Polymorphism = same method name, different behavior per class.
    • 
        
  • Python dictionary: d[k] = v, del d[k], d.get(k, default), d.pop(k, default), d.popitem(), d.setdefault(k, v), d.items(), d.clear().
    • 
        
  • Python list: append, extend, insert(i, x), remove(x) (first match), pop() (last), index, count, sort, reverse, copy. Java ArrayList: add, get, set, remove, size.
    • 
      


      
9. Tracing code without mistakes (the hardest section)

      
    
        
  • Write a small table with one column per variable. Update it line by line. Don't do it in your head.
    • 
        
  • Check the loop edges: < vs <=, and where the counter starts.
    • 
        
  • range(a, b) and slices stop before b.
    • 
        
  • "How many times is F called" is not the same as "what does F return."
    • 
        
  • By value = a photocopy (original unchanged). By reference = the original (it changes).
    • 
        
  • Integer division drops the decimal: 7 / 2 = 3. % is the remainder.
    •
